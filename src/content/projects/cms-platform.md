## 背景

企业官网、帮助中心、博客社区、产品文档等场景各自维护内容系统，能力重复、体验割裂。目标是建设统一 CMS 中台，为企业内部多个内容场景提供一致、高效、可扩展的管理服务。

## 我做了什么

- 从零搭建 React 版中台前端，基于 Next.js 实现 SSR 与 CSR 混合渲染，兼顾首屏性能与 SEO。
- 实现内容编辑与管理界面：富文本与 Markdown 双模式、媒体资源管理、版本管理、定时发布；基于 WebSocket 支持多人协作编辑与实时保存，集成草稿自动保存与一键导入导出。
- 设计统一的内容服务调用层（`useContentService`），用泛型与策略模式支持多存储后端切换、内容格式转换与错误统一处理，结合 React Query 做缓存、自动刷新与状态管理。
- 针对内容列表与媒体库等长列表场景引入 `react-window` 虚拟滚动，万级数据下保持 60fps。
- 封装内容选择器、富文本工具栏、媒体资源管理器等组件，用 Storybook 做组件开发与文档展示。
- 实现版本管理与审批流：草稿与发布分离、版本回溯、变更对比、多级审核，通过差异算法与快照策略控制存储成本。
- 构建管理端应用：内容配置、权限管理、站点管理、统计分析、异常监控；基于 Docker + GitHub Actions 做多环境部署。

## 结果

多类内容场景统一接入，编辑体验与发布效率提升，内容资产集中管理、可追溯。
