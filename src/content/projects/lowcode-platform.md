name: 统一低代码平台
period: 2025.04 — 2025.09
role: 前端负责人 · 从 0 到 1
audience: 业务运营、实施人员与前端开发
summary: 把页面搭建做成可视化平台，组件协议、拖拽编排与数据绑定一次打通。
thesis: 页面重复开发，把搭建能力做成平台，而不是再做一套模板。
category: infra
context: 内部管理系统、营销活动页、数据看板、移动端 H5 等页面重复开发成本高，业务方需要更快的页面交付方式，而不是每个场景再做一套模板。
goals:
  - 让业务方通过可视化搭建快速交付页面。
  - 统一多组件库的注册、属性绑定与事件模型。
  - 支持 API 绑定、跨组件通信、条件渲染与发布管理。
constraints:
  - 表单、图表、布局与业务组件来自不同组件库，属性与事件模型不一致。
  - 千级组件树下拖拽容易掉帧。
  - 只解决拖拽不够，接口联动与条件渲染仍需回到代码。
flow:
  - name: 组件物料
    detail: 多组件库统一注册与协议
  - name: 可视化编排
    detail: 拖拽、属性配置与页面预览
  - name: 数据与状态
    detail: API 绑定、跨组件通信与条件渲染
  - name: 发布与管理
    detail: 版本、权限与资源统计
decisions:
  - title: 组件注册先统一协议
    problem: 表单、图表、布局与业务组件来自不同组件库，属性和事件模型不一致。
    choice: 用 useComponentService 以泛型与策略模式统一注册、属性绑定与事件处理。
    benefit: 接入新组件库只需适配协议，编辑器本身不用为每个库写分支。
  - title: 编辑器性能取决于更新粒度
    problem: 千级组件树全量重渲染，拖拽会明显掉帧。
    choice: 虚拟渲染、增量更新与组件懒加载，只处理发生变化的部分。
    benefit: 千级组件数量下保持 60fps 交互，复杂页面仍然可以编辑。
  - title: 低代码的边界在数据流
    problem: 只解决拖拽，页面一旦需要接口联动与条件渲染，仍然要回到写代码。
    choice: 设计数据源与状态管理，支持 API 绑定、静态数据、跨组件通信与条件渲染，用响应式依赖追踪控制更新范围。
    benefit: 常见业务页面可以在平台内闭环，复杂逻辑仍保留扩展空间。
checks:
  - 接入新的组件库，是否需要修改编辑器核心代码？
  - 千级组件页面拖拽时，帧率与操作延迟是否可接受？
  - 页面发布后，数据绑定与条件渲染是否与编辑态一致？
outcome: 多个业务场景通过搭建快速交付页面，重复开发明显减少，组件资源集中管理与复用。
responsibility: 负责低代码平台前端从 0 到 1 的架构与编辑器实现，包括组件协议、可视化编排、数据流与管理端。

  owned:

    - Docker 化构建与 CI/CD 部署。
  team:

    - 与后端联调页面发布、权限与资源接口。
